# BatchKart Phase 1a — Database & Auth Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the complete BatchKart PostgreSQL schema on Supabase — 29 tables across six domains plus multi-tenant coaching, with enums, indexes, triggers, Row Level Security on every table, a pg_cron archive job, storage buckets, curated seed data, and generated TypeScript types wired into the app's Supabase clients — verified by pgTAP tests in CI.

**Architecture:** All database state lives in versioned SQL migrations under `supabase/migrations/`, applied deterministically by `supabase db reset`. Migrations are grouped by domain (one file per domain) so files that change together live together. Behavioral logic (auto-create-profile trigger, `updated_at` touch, rating recompute, `search_vector` maintenance, requirement auto-archive) is implemented as Postgres functions + triggers and proven with pgTAP tests. RLS follows the spec's "one rule, two worlds" model: a small set of `SECURITY DEFINER` helper functions (`is_admin()`, `current_profile_role()`, `is_active_member_of()`, `can_manage_branch()`) drives permissive policies that give anon read-only access to *published* catalog rows, students full access to their own rows, coaching-admins branch-scoped write (schema-ready, no UI yet), and super-admins unscoped CRUD. TypeScript types are generated from the live schema so the app is fully typed end-to-end.

**Tech Stack:** Supabase (PostgreSQL 15+, CLI, local Docker stack), pgTAP (`supabase test db`), SQL, `@supabase/ssr` (already wired in Phase 0), TypeScript, GitHub Actions.

**Conventions for every task:**
- Run commands from the project root (`C:\Users\sagar\OneDrive\Desktop\Websites\BatchKart`) in PowerShell unless noted.
- UUID primary keys via `gen_random_uuid()`; `created_at timestamptz not null default now()` and `updated_at timestamptz not null default now()` on every table; `deleted_at timestamptz` only where the spec calls for restorable soft-delete.
- Every table gets `alter table ... enable row level security;` in the same migration that creates it (verified globally in Task 16).
- DDL tasks use **verify-by-running** (`supabase db reset` applies cleanly); behavioral tasks (triggers, RLS, functions) use **TDD** with pgTAP.
- Commit at the end of each task.

- [ ] **Step 1: Write the migration**

```sql
-- profiles: 1:1 with auth.users, auto-created on signup.
create table public.profiles (
  id uuid primary key references auth.users (id) on delete cascade,
  role public.user_role not null default 'student',
  full_name text,
  email text,
  phone text,
  whatsapp text,
  avatar_url text,
  city_id uuid,  -- FK added in taxonomy migration to avoid ordering coupling
  onboarding_completed boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
alter table public.profiles enable row level security;
create trigger profiles_set_updated_at
  before update on public.profiles
  for each row execute function public.set_updated_at();

-- admin_users: super-admin credentials + PIN. No public signup.
create table public.admin_users (
  id uuid primary key default gen_random_uuid(),
  profile_id uuid not null unique references public.profiles (id) on delete cascade,
  security_pin_hash text not null,          -- bcrypt/argon hash of 8-digit PIN (computed app-side)
  permissions jsonb not null default '{}'::jsonb,
  last_login_at timestamptz,
  last_ip inet,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
alter table public.admin_users enable row level security;
create trigger admin_users_set_updated_at
  before update on public.admin_users
  for each row execute function public.set_updated_at();

-- notifications
create table public.notifications (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references public.profiles (id) on delete cascade,
  type public.notification_type not null,
  title text not null,
  body text,
  data jsonb not null default '{}'::jsonb,
  read_at timestamptz,
  created_at timestamptz not null default now()
);
alter table public.notifications enable row level security;

-- Auto-create a profile row whenever an auth user is created.
create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer
set search_path = public
as $$
begin
  insert into public.profiles (id, email, full_name)
  values (
    new.id,
    new.email,
    coalesce(new.raw_user_meta_data ->> 'full_name', new.raw_user_meta_data ->> 'name')
  )
  on conflict (id) do nothing;
  return new;
end;
$$;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();
```
